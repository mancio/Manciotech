# Manciotech

[Manciotech](https://manciotech.net/) is a React and TypeScript website with recipes, kitchen calculators, game utilities, AI services, and a stock screening report. The site supports English, Italian, and Polish.

| Page | What it offers |
| --- | --- |
| [Recipes](https://manciotech.net/recipes) | Searchable recipes with scalable ingredient quantities |
| [Kitchen tools](https://manciotech.net/kitchenTools) | Dough and hydration calculations |
| [Score counter](https://manciotech.net/score) and [dice](https://manciotech.net/Dice) | Scorekeeping for card games and a virtual dice roller |
| [Temperature](https://manciotech.net/Temp) | Sensor readings from Firebase Realtime Database when configured |
| [AI services](https://manciotech.net/services) | AI services and browser tools |
| [Stocks](https://manciotech.net/stocks) | Static report generated by the Python stock screener |

## Run the website locally

Use Node.js 20 and npm to match GitHub Actions. From the repository root, run:

```sh
npm install
npm start
```

Open [localhost:3000](http://localhost:3000). The stock report is available locally at [localhost:3000/stocks.html](http://localhost:3000/stocks.html).

```sh
npm run typecheck
npm test -- --watch=false --runInBand
npm run build
```

The production build writes to `build/`. The [post-build script](scripts/build-seo.cjs) generates HTML for site routes and localized recipe pages, plus the sitemap, robots file, and 404 page.

### Configure temperature readings

To enable live readings, add these values from your Firebase web app and Realtime Database settings to a root `.env` file:

```dotenv
REACT_APP_API_KEY=
REACT_APP_PROJECT_ID=
REACT_APP_DATABASE=
```

`REACT_APP_DATABASE` takes the Realtime Database URL. Restart the development server or rebuild after changing these values. The rest of the website can run without this configuration.

## Generate the stock report

Use Python 3.12 to match the [report workflow](.github/workflows/update-stocks.yml). Copy [`stocks/.env.example`](stocks/.env.example) to `stocks/.env` and set `FINNHUB_API_KEY`. The workflow uses `DEMAND_PROVIDER=derived`, which needs no additional provider key.

From the repository root, run:

```sh
cd stocks
python -m pip install -r requirements.txt
python -m pytest tests -q
python -m src.main
```

The generator writes `stocks/report.html`. To preview the refreshed report in the website, copy it to `public/stocks.html` and open `/stocks.html` on the development server.

## Deploy to Firebase Hosting

The [website workflow](.github/workflows/deploy-website.yml) deploys relevant changes pushed to `main` and can also be run manually. The [stock report workflow](.github/workflows/update-stocks.yml) runs weekdays at 21:17 UTC or on demand. It tests the screener, generates the report, builds and deploys the site, and commits any change to `public/stocks.html`.

Both workflows use the `FIREBASE_SERVICE_ACCOUNT_MANCIOTECH_244AC` repository secret. The report workflow also uses `FINNHUB_API_KEY`.

For a manual deployment, install the Firebase CLI and sign in with an account that has Hosting access. From the repository root, run:

```sh
firebase login
npm run build
firebase deploy --only hosting
```

[.firebaserc](.firebaserc) selects `manciotech-244ac`. [firebase.json](firebase.json) serves `build/` with clean URLs and no trailing slash, so generated pages and the stock report can be opened directly at their public paths.
